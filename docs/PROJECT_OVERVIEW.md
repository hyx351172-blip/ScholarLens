# ScholarLens 项目说明

*范围与能力快照：2026-09-27；按当前工作区核对，不代表已发布版本。*

---

## 🎯 项目定位

ScholarLens 面向需要精读和比较科研论文的学生、研究人员及技术从业者。用户上传有权处理的 PDF，在指定知识库内提问，并沿回答引用查看论文、页码与原始片段。

核心问题是：普通文本切片容易割裂表格、公式与解释；检索到的文本也未必对应用户指定论文；即使答案附带引用，引用也不一定充分支持结论。因此，本项目分别处理论文结构、检索范围和证据展示，并将“来源真实”与“语义支持”分开评测。

项目不是自动写论文系统，不替代原文阅读、领域判断或事实复核。

## 🔗 架构与职责

前端为 React + TypeScript + Vite，后端为四个 FastAPI 服务，向量库使用 Milvus。服务级数据流见 [根 README](../README.md)。

| 模块 | 入口或目录 | 职责 |
| --- | --- | --- |
| PDF 与入库编排，8006 | `backend/Information-Extraction/unified/` | 接收 PDF；解析、后处理、保存产物并组织切分和入库 |
| 结构化解析 | `unified/parsers/` | Docling 适配、阅读顺序、章节树、逻辑表、图/公式关系、可选 VLM repair |
| 科研切分 | `unified/chunkers/structure_aware_chunker.py` | 在 8006 内直接生成结构化 chunks，不单独监听端口 |
| 通用切分，8001 | `backend/Text_segmentation/` | 处理快速/VLM 路径的 Markdown 切分 |
| 存储与检索，8000 | `backend/Database/milvus_server/` | Embedding、向量入库、检索、知识库及文档查询、PDF/切片访问 |
| RAG 问答，8501 | `backend/chat/` | 文档范围约束、召回编排、可选规划/重排、上下文与答案引用 |
| 阅读界面，5173 | `frontend/` | 文献库、上传、文档详情、对话和证据抽屉 |
| 评测 | `scripts/`、`tests/`、`harness/` | 阶段测试、冻结实验、运行记录、质量门与实验比较 |

### 入库路径

1. 前端提交 PDF 与模式配置。前端默认 `docling`，上传 API 默认 `fast`，两者不能混为一谈。
2. Docling 结果映射为 `PaperDocument` 与 `ContentBlock`；按阅读顺序、章节、表格及图/公式关系进行后处理。
3. `StructureAwareChunker` 利用这些关系形成可追溯的 chunks；超长逻辑对象可以拆成多个 chunk，不保证“一张逻辑表永远只占一个 chunk”。
4. 解析服务保存产物，并将 chunks 交给 Milvus API 生成向量及入库。快速/VLM 路径则先调用独立 Markdown 切分服务。

### 问答路径

1. 接收知识库、问题与历史消息，解析当前问题中明确指定的论文范围。
2. 默认进行 Dense 召回、阈值过滤和应用层证据选择；显式范围约束贯穿检索和返回候选。
3. 可选多查询规划将问题拆成子查询，以 Query RRF 与覆盖选择融合多路 Dense 结果；失败处理遵循范围约束，不静默扩大到其他论文。
4. 默认 `legacy` 根据上下文生成回答，经过输出检查后返回答案及来源；前端按 `[Sx]` 打开证据并定位 PDF 页码。

### 追溯信息与边界

解析侧保留 `paper_id`、`file_id`、block 类型、页码、bbox、`section_path` 和 relations；切分/检索侧保留 chunk 与来源 block 的关联。章节路径可用于正文与非正文片段，不只是标题自身的属性。

`PaperMetadata` 已定义标题、作者、年份、DOI、arXiv ID 等字段，但字段存在不代表都已可靠抽取和填充。页码正确也不保证图表的语义章节归属正确；需要以实际产物和原文复核。

## 📊 如何解释已有结果

验收按层次解释，不用一个“准确率”概括所有能力：

- **链路完整性**：三篇论文共 57 页、205 chunks 完成上传到索引；不是逐页结构正确率。
- **机械契约**：原始多论文测试 13/16；文档范围修复后，同批题在线回归 16/16；不是独立测试集上的问答准确率。
- **引用定位**：检查来源 ID、文本和页码对应关系；不能替代断言是否受证据支持的判断。
- **语义实验**：区分人工 Gold、AI 初审、模型评审和未裁决样本；错误、中止、未运行项均保留。
- **代码回归**：最近记录为 844 项测试通过；237 项对齐指专用 `tests/traceability` 目录。本轮未重跑全量测试，全 `tests` 追踪另发现 5 个早期编号位于技术设计、未纳入规格扫描，详见 [检查记录](evaluation/README.md)。

报告入口：[评测索引](evaluation/README.md)。各报告保留当时的模型、参数、数据划分及版本限制，不将不同题目、不同证据或离线回放分数混成总分。

## ⚠️ 已知限制与收尾原则

当前主要限制是复杂表格/OCR/公式误差、图表语义章节归属、自然语言论文别名覆盖、细粒度引用支持，以及尚未完整验收的浏览器异常路径。当前验证偏向指定科研论文和开发案例，不保证任意领域或中英文论文具有相同效果。

保留默认问答流程和已有实验产物；暂停追加表格与核验器优化。后续优先处理阻碍正常使用的错误，而不是为单个失败题反复扩大规则或付费评测。

本轮仅做文档收尾。演示与录屏暂缓；公开发布前仍需审查未提交改动、密钥与数据、依赖许可及复现边界。现有手动测试和追踪门不应写成已经由 CI/hook 强制执行。
