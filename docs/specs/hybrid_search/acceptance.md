# Optional lexical + semantic retrieval

- AC-5101: Existing requests default to Dense and keep their candidate ordering and score threshold. Hybrid is explicit in `/search`, `/chat` and the chat settings UI.
- AC-5102: BM25 searches the complete scoped chunk corpus, not only the Dense candidate list. Tokenization is deterministic (NFKC/casefold, words/numbers and CJK bigrams); unknown/empty queries return no lexical hits. No paid lexical service or new dependency.
- AC-5103: Equal-weight RRF (k=60) combines independent Dense and BM25 rankings with deterministic ties and no repeated contribution. Retain dense_score, bm25_score, hybrid_rrf_score and branch ranks; never compare an RRF score to a cosine threshold.
- AC-5104: Both branches use the same collection/filter. Read current rows every Hybrid request using a closed iterator (Strong consistency); empty scopes skip Embedding. Fail explicitly on iterator errors, 15-second scan timeout, or a corpus over 20,000 chunks / 64 MiB retrieval text; do not silently truncate/fall back to Dense.
- AC-5105: Existing section selection, document coverage, multi-query and citation paths accept Hybrid results and expose branch provenance. Dense behavior remains unchanged. Failed Hybrid contracts fail closed rather than generating from a mislabeled Dense response.
- AC-5106: A network-free A/B runner validates dataset/baseline IDs, cases, counts, all hit/gold chunk identities and available metadata; fingerprints source artifacts, reconstructed retrieval text and inputs. Report Dense, BM25, Hybrid Top-10 and paired outcomes separately for v1 and previously used v2. State replay limitations and no-answer limits; do not claim generation improvement or independent held-out performance.

Plan: RED core/API/chat tests -> dependency-free BM25/RRF -> opt-in Milvus/chat/UI -> offline same-corpus A/B -> regression/build/traceability. Keep current checkout because prior acceptance changes are active here; preserve them. No commit/push, paid Embedding/generation, schema migration, Reranker or parameter tuning in this feature.

Contract: `/search` adds retrieval_mode=dense|hybrid, hybrid_candidate_k=50 (1..500), dense_score_threshold=0 (-1..1). Top-K must be positive; only Hybrid bounds it to 500, leaving valid Dense large-K requests unchanged. Hybrid uses max(top_k, hybrid_candidate_k) per branch and returns Top-K. `/chat` adds retrieval_mode with Dense default, passes its existing threshold only to the Dense branch, and retains positive lexical hits. `score` is RRF for Hybrid before optional downstream ranking; explicit `score_type` and original scores describe its meaning. Hybrid chat HTTP timeout is 60s (Dense remains 30s), to accommodate the bounded extra scan.

Experiment: rebuild target=600/max=900 chunks from the saved 19 parser documents, validate exactly 2,057 chunks against both historical datasets, then fuse cached Dense Top-10 with new BM25 Top-10. Equal weights, BM25 k1=1.2/b=0.75 and RRF k=60 are fixed before execution. Historical Dense Top-50 vectors/ranks are unavailable; online candidate-50 equivalence and live latency are not established. Gold sets have incomplete relevance judgments; NDCG is relative to these annotations only. No-answer retrieval hits are not false answers without a generation test.

Sources: [Lucene BM25](https://lucene.apache.org/core/9_12_1/core/org/apache/lucene/search/similarities/BM25Similarity.html), [RRF](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion), [Milvus query iterator](https://milvus.io/api-reference/pymilvus/v2.6.x/ORM/Collection/query_iterator.md). BM25 math follows these defaults; our tokenizer is not Lucene's analyzer.
