# 逐条结论绑定引用：实现与离线验收

日期：2026-09-26。状态：后端 opt-in 功能完成，真实模型效果未验证。

## 本轮目标与结论

新增 `answer_mode="claim_bound"`，让模型先输出每条结论及其证据编号，
由程序校验并生成网页使用的 `[S1]` 引用。默认仍为 `legacy`，不改变现有
网页请求的行为。本轮没有调用付费 API、重启服务、修改前端、提交或推送。

这是生成端的引用结构约束，不是新一轮语义评审，也不是语义正确性保证。
`claim_bound_passed` 只表示结构及引用来源校验通过；响应始终标记
`semantic_verified: false`。

## 为什么做这一步

复核 v3.1 的 AI 草稿后，不能把评审标签直接当成人工真值：

- A01-C003 / X01-C013 暴露了结论限定词与自身引用之间的支持缺口。
- B01-C001 是列表引导句没有自身引用，不等同于整段事实幻觉。
- L01-C008 / X01-C011 的 supported 也有范围泛化、引入外部常识的疑点。
- X02-C006 可能混淆冻结原始权重与应用低秩更新，不能按标签盲目改产品。
- L03-C009 的截断错误、损坏分式和 A03-C005 的指代问题仍保留。

因此先约束生成端“谁引用谁”，不自动改历史分数，不填人工标签，不在本轮
同时修 PDF 公式或改评审器。详见 [原复核草稿](subject-scope-audit-v31-review.json)。

## 处理流程与接口

最终检索 / 重排结果 → 无损证据编号 → 一次 JSON 生成 → 全量校验 → 文本与引用渲染。

在现有 `POST /chat` 请求体中额外加入：

```json
{"answer_mode": "claim_bound"}
```

这只是需要合并到原请求的字段，不是完整请求；其余知识库、问题、模型配置
保持原接口约定。省略字段或使用 `legacy` 返回旧模式。未知值返回 422。
此代码尚未重启到运行中的服务，网页也尚未发送新字段。

程序按最终来源顺序分配 `S1`、`S2`，在每个 `chunk_text` 内生成
`S1:E0001` 等编号。每段默认不超过 480 个 Unicode 字符，可按相邻编号联合阅读。
文本不归一化、不删除符号，跨度为相对原始 `chunk_text` 的 Python 字符索引
`[start, end)`，不是 PDF 页坐标，也不是 JavaScript UTF-16 索引。
这些段是引用定位锚点，不是重新切分并写入 Milvus 的 chunks。

模型必须返回：

```json
{
  "status": "answered",
  "claims": [
    {"text": "编码器包含六层。", "evidence_ids": ["S1:E0001"]}
  ]
}
```

程序渲染为 `编码器包含六层。 [S1]`。联合证据可列出多个编号，重复来源只生成
一个来源标记。不允许模型提供自己的摘录、来源编号或坐标。
`metadata.citation_binding.claims` 保存结论文字、答案内起止索引、来源编号
和证据起止索引，便于后续 harness 精确复核。

证据不足的合法输出为 `{"status":"insufficient","claims":[]}`。
无检索结果沿用原 `no_evidence` 早退路径，不调用生成模型、不附新 binding。
其余新模式状态包括 `claim_bound_insufficient`、`invalid_claim_evidence`、
`invalid_claim_structure`、`incomplete_claim_generation`。

## 安全与兼容边界

- 最多 50 个来源，总原文不超过 120,000 字符；超限直接拒绝，不静默截断原文。
- 最多 20 条结论，每条 1,200 字符、8 个证据编号，原始输出最多 40,000 字符。
- 拒绝未知 / 重复编号、重复 JSON key、额外字段、非法 JSON、过深 JSON、
  已写入的来源标记、控制字符、换行、代码及 HTML；句界启发式拦截明显多句。
- 数学表达、小数及常见英文缩写有例外；该启发式不是语言学句子分析器，
  不能保证语义原子性，也可能拒绝罕见合法缩写。
- 任一条非法，则不输出其他部分结论；不猜引用、不修公式、不调用第二个模型补救。
- 流式与非流式共用校验函数。流式接口仍返回 NDJSON，但等待完整校验后再发内容，
  不向前端展示未经校验的 JSON / token。
- 生成端单次请求，SDK `max_retries=0`、网络超时配置为 60 秒，生成 token 上限
  沿用请求的 `llm_config.max_tokens`；没有新增固定 token 上限，也不承诺整条 RAG
  请求总耗时在 60 秒内。检索规划 / 重排仍走已有逻辑，不计入这一次生成请求。
- 拒绝截断、拒答及空输出；生成服务异常转为固定提示，不透出原始供应商异常或密钥。
- 历史只用最近 10 条、每条最多 4,000 字符辅助识别对象；历史 system 消息被忽略。
  自定义模板作为数据中的格式偏好，不再覆盖新模式的 JSON 系统约束。
- 来源结构和默认模式保持兼容，`return_source=false` 仍不返回原文。
  新 metadata 仅包含引用标识与坐标，不复制 API key 或原始模型响应。
