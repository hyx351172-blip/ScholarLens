## v2 如何工作

输入是经过校验的原 v1 packet；完整包作为 `base_packet` 保存，证据不增加、不重切，
不借用其他断言的引用。外层 `packet_id` 绑定 v2 策略、原始 packet 和确定性的风险词提示。

| 检查项 | 模型必须核对 | 程序检查 |
| --- | --- | --- |
| content | 所有事实、否定、数量、比较、公式是否得到支持 | 必填有效状态，支持/反驳须有精确引用 |
| scope | 主体、群体、频率、默认设置是否与证据范围一致 | 必填依据类型和范围关系；限制单例支持一般化 |
| conditions | 断言和证据中的必要条件是否保留 | 缺失条件、未决条件不能通过整体门控 |

模型输出没有总体 verdict 字段；程序按三项检查计算最终结果。
全部为 entailed 才可能放行；明确 contradicted、missing、uncertain 分别保留为
反驳、缺少支持、弃权，不混在一个“回答失败”中。整段候选答案不自动裁剪、改写或修补。

### 范围约束

- scope 的依据类型包括 explicit_statement、aggregate_evidence、single_example、inference、none。
- 若断言含一般化提示，而模型仍以单例、推断或无依据声称 entailed，程序将范围检查降为 missing。
- 若模型报告 claim_broader，即使其原始状态为 entailed，也不能放行；unknown alignment 则不能被当作范围已确认。
- 不是见到 often/所有/默认就拒绝：正确的明确范围陈述或相关汇总证据仍可通过。
- 对 not all/not always、并非所有/并不总是等直接否定全称短语，保留“一个反例可支持”的可能，避免简单量词拦截。
- 每条断言都要填写范围和条件检查，**即使没有命中任何关键词**。

风险词识别只是有限的中英文词法提示，不是完整自然语言逻辑解析器。
未覆盖的同义词、复杂否定作用域、嵌套量词仍可能产生漏报/误报；这些都要靠真实评测发现。

### 引用契约

每项检查须提供简短理由；支持/反驳至少一个、最多三个原文引用。
引用只能来自本条选择的 anchors，程序检查 quote 必须为其中唯一出现的精确子串，
再计算源文本坐标。重复/伪造/跨来源/歧义摘录、缺失字段、错包响应、JSON 异常均拒绝。
旧版模型回答不能补字段后冒充 v2 已执行，必须重新核验。

## 重要限制：本轮不是“模型语义错误已修好”

程序能检查响应格式、原文出处和**模型自己报告的信息之间的一致性**。
它不能仅凭 Python 判断某句话究竟是总体规律还是单例，也不能证明模型的 entailed 为真。
若模型把单例错误标成 explicit_statement、把遗漏条件标成已满足，仍可能通过结构校验。

测试专门保留了这个边界：一份语义上不可靠但结构自洽的注入响应可以通过，
`semantic_verified` 与 `human_verified` 始终为 false。
不能拿单元测试“能挡住自报单例的泛化”宣称已修复真实模型的 847 错误。

此外，v2 不做自动原子事实拆分，也不修复科研缩写的单句识别、PDF、chunker、检索或生成器。
