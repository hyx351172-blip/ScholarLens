## 修改内容

### 分号不再导致整份回答被拒绝

新增 `backend/chat/claim_bound_output_v2.py`，供生产 `claim_bound` 分支使用。正文中的中英文分号改为非阻断的 `compound_clause` 警告，保留模型的完整 claim 文本及原始 evidence ID 选择。

不会自动拆句、改写事实、丢弃后半句或补充证据。公式中的分号不会触发正文警告。警告仅表示存在复合分句，并不证明该 claim 已经是单一原子事实，也不证明全部分句均受所选证据支持。

未知、缺失、重复证据 ID，以及非法 JSON、额外字段、重复字段、超长输出、多完整句、控制字符、注入的引用标记、HTML 等硬校验保留。任一 claim 不合格时仍拒绝整份输出，不泄漏部分答案。

### 失败原因与提示分开

| 状态 | 返回给用户的提示 |
| --- | --- |
| `invalid_claim_structure` | 模型回答未通过格式或引用校验，本次未展示答案。请重试。 |
| `invalid_claim_evidence` | 检索结果未通过输入校验，暂时无法生成回答。请缩小问题范围或重试。 |
| `incomplete_claim_generation` | 模型未返回可用的完整回答，本次未展示答案。请重试。 |
| `claim_bound_insufficient` / `no_evidence` | 保留原有证据不足提示，分别对应模型返回 insufficient / 空检索结果。 |

以上区分针对 claim-bound 路径；`legacy` 路径未改。非流式 JSON 与流式 NDJSON 返回一致；新增 warning 元数据是兼容性扩展，不需要前端修改才能显示上述提示。没有自动重试或回退生成。
