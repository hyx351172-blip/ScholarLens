# 完整句级证据模式：离线验收 v2

日期：2026-09-27。状态：**候选功能已实现、离线验收通过，未默认启用，未进行真实模型复测。**

## 本轮解决了什么

旧模式按约 480 字符切细锚点，会把一句原文切成两部分。本轮增加 `sentence_v2`：优先按句子、段落或 Markdown 表格行形成证据单元，保护常见缩写、小数、URL、行内公式与普通折行；所有字符和来源坐标仍来自原始 chunk，不改写或补齐原文。

单元过长时按硬上限 960 字符形成显式续段，每单元最多 8 段。引用这种单元必须由模型在同一条 claim 中显式选齐各段，程序不会补引用，也不能借另一条 claim 的引用。超长不可切公式、超过分段/目录上限等输入在模型调用前拒绝，不隐式截断。

新编号使用 `S1:U0001`，续段为 `S1:U0001:P01`，与旧 `S1:E0001` 隔离。新目录拒绝旧编号，防止同一个编号悄悄指向不同原文。

生成提示同时强调：只回答相关事实，逐条核对数值、维度、采样条件与限定词；不要把“本研究”扩大为“方法默认”，不要猜测压平分式的运算符。这是提示约束，**不是自动语义验证器**。

## 如何使用

在已有 `/chat` 请求中额外指定：

```json
{
  "answer_mode": "claim_bound",
  "claim_evidence_mode": "sentence_v2"
}
```

该片段仅展示新增选项，完整请求仍需问题、集合和模型配置等原有字段。

默认仍是 `answer_mode=legacy`；显式选择 `claim_bound` 但未指定新字段时仍使用 `fixed_v1`。新字段只影响 claim-bound 路径。没有修改前端开关，也没有重启运行中的服务。

JSON / NDJSON 共用相同入口。新模式在 `citation_binding` 中增加 `evidence_catalog_version=sentence_v2`，并在证据位置记录 `unit_id/part/parts`；页面引用仍是 `[S1]`，原有 source 字段保持兼容。缺失续段返回 `incomplete_evidence_unit` 及固定的“模型引用的原文续段不完整”提示，不显示半份回答。

## 代价与尚未解决的问题

11 个非空请求的 system + user 文本共从 **167,078 字符增至 277,010 字符，增加 65.8%**。主要来自更细的编号、重复定位字段和新增指令。字符不是 token，也不能换算为本次费用、延迟或计费涨幅；本轮没有新 usage 数据。

因此不据此切换默认。小规模真实生成需要同时验证引用选择、输出完整率、实际 token 与延迟；如果收益不足，应压缩目录表示或撤回候选方案。

- B01：句子现在完整，但模型是否仍把采样比例错说成预测概率，尚未复测。
- L03：矩阵维度与初始化仍在不同单元，模型必须分别选证据；没有把邻近内容自动算成已引用。
- L01 / L03：原文 `α r` 原样保留，没有补成 `α/r`；是否遵守省略模糊公式的指令，尚未复测。
- X02：限定研究范围靠提示约束，不能靠合法 ID 检出过度推广。
