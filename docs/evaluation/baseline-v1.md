# ScholarLens Dense Retrieval Baseline v1

## 1. 结论

当前 Dense RAG 已能稳定完成单篇论文的事实和机制问答，但尚不能可靠完成跨论文比较，也会在“命中了正确论文、却没有命中正确证据”的情况下生成不完整或过度推断的回答。

本轮最重要的两个失败案例：

- Q03 命中 GAAP 论文，但没有召回定义缩写的摘要 Chunk，最终错误回答“GAAP 全称未知”。
- Q09 跨论文比较仅召回 MAP-Graph，完全没有召回 MemLineage 主文，却仍生成了双论文比较，存在来源不足和幻觉风险。

因此，当前系统可以作为 ScholarLens 的 Dense 检索基线，但还不能宣称具备可靠的科研论文对比能力。

### 3.3 解析质量发现

#### 表格结构漏识别

通过 `Table N`、Markdown 分隔行等信号共发现 58 个疑似表格相关 Chunk，但系统只标记了 18 个 `table_like`，标记覆盖率仅为 31.0%。

| 文件 | 疑似表格相关 Chunk | `table_like` | 主要现象 |
|---|---:|---:|---|
| CharacterEval | 14 | 11 | 大型 Markdown 表格跨 Chunk，后半段缺少表头 |
| GAAP | 8 | 0 | 表格多数被线性化为普通文本 |
| MemLineage | 22 | 7 | Markdown 表格与普通文本表格混合，Caption 经常与数据分离 |
| MAP-Graph | 14 | 0 | 表格引用存在，但没有任何 Chunk 被识别为表格 |

这解释了 Q01 中模型对正文与表格计数差异进行无依据推测：检索虽然找到了数字，但表格结构未被稳定保存，模型无法可靠判断表头、行列和 Caption 的对应关系。

#### Bridge Chunk 占比较高

66/367（18.0%）为跨页 Bridge Chunk。Bridge 有助于保留跨页上下文，但当前固定截取边界文本，可能产生：

- 与相邻正常 Chunk 重复的内容；
- 半行表格或缺少表头的表格片段；
- 页码、页眉和参考文献边界噪声；
- 检索 Top-K 被近似重复片段占用。

后续应将 Bridge 与普通 Chunk 分开评测，并禁止对表格使用固定字符截断式 Bridge。

#### 图片与路径噪声

共发现 2 个疑似以图片路径为主体的 Chunk，分别来自 GAAP 和 MemLineage。数量不大，但这类 Chunk 不具备独立语义，不应参与 Embedding 检索。建议在入库前过滤纯图片引用，并把图片与相邻 Caption、段落绑定为多模态证据。

#### Chunk 长度分布过于规则

所有 Chunk 均在 301–1,795 字符之间，且平均约 1,068 字符，说明切分器较好地执行了长度约束。但长度稳定不代表语义完整：当前仍会在表格行、Caption 与表格主体、跨页论述中间切断。下一阶段应从“长度优先”升级为“论文结构优先”。

### 3.4 解析与切分阶段结论

| 维度 | 结论 |
|---|---|
| 文件级成功率 | 4/4，合格 |
| 文本可读性 | 正文整体可用于 Dense 检索 |
| 页码保留 | 已保留 `page_start/page_end/pages` |
| 表格保真度 | 不合格，是当前最明显的解析缺陷 |
| 跨页连续性 | 有 Bridge 机制，但重复和截断风险较高 |
| 图片处理 | 已提取图片，但尚未形成可检索的图文联合证据 |
| 科研元数据 | 尚缺标题、作者、章节、DOI/arXiv ID 等统一字段 |

## 6. 发现的问题

### P0：跨论文问题缺少检索覆盖约束

单个全局 Dense Top-K 容易被语义更接近的一篇论文占满。Q09 的 10 个来源全部来自 MAP-Graph，导致模型只能依据一篇论文评价两篇论文。

建议加入 query decomposition：先识别需要比较的论文，再对每篇论文分别检索 Top-K，最后合并上下文。

### P1：文档级命中掩盖证据级失败

Q03 虽然命中 GAAP 文件，但 Top-10 没有包含摘要中 `Guaranteed Accounting for Agent Privacy` 的定义。应建立带 `file_id + page + chunk_index` 的证据标注，使用 Recall@K、MRR 和 nDCG 评估。

### P1：生成回答过长并出现过度推导

Q01、Q02 在核心答案正确后继续解释数据差异、推导未完整提供的指标，增加了幻觉风险。当前 Prompt 只有宽泛的“准确、详细”，缺少：

- 只回答问题所需范围；
- 每个关键结论必须有来源支持；
- 不得根据计数关系猜测缺失指标；
- 来源不足时明确区分已知与未知。

### P2：延迟主要来自生成阶段

平均检索仅 2.41 秒，平均生成达到 24.77 秒。回答过长同时降低准确性和响应速度。应先限制答案结构和 token，再考虑更换模型或缓存。

### P2：表格结构仍会影响证据质量

CharacterEval 的统计表存在跨 Chunk 和结构不完整问题。虽然 Q01 依靠正文成功回答，但模型注意到了正文与表格计数差异并进行了无依据解释，说明表格感知切分仍是必要改进。

## 7. 下一轮实验

保持同一问题集，依次对比：

1. Dense v1：当前结果。
2. Dense + 论文过滤：跨论文题按论文分别召回。
3. Dense + Reranker：验证 Q03 的定义 Chunk 能否前移。
4. BM25 + Dense + RRF：提升缩写、数字和专有名词检索。
5. Hybrid + Reranker + evidence-aware prompt：作为目标版本。

下一轮最低验收目标：

- 严格证据命中率 ≥ 90%。
- 跨论文题每篇目标论文至少返回 2 个来源 Chunk。
- 无答案正确拒答率保持 100%。
- 平均总延迟 ≤ 20 秒。
- 答案中的关键事实能够定位到文件、页码和 Chunk。

## 8. 复现方式

确保四个后端服务已启动，然后运行：

```powershell
python scripts/run_baseline.py
```

可只运行指定问题：

```powershell
$env:BASELINE_CASE_IDS='Q03,Q09'
python scripts/run_baseline.py
```

脚本只从根目录 `.env` 读取模型配置，不会输出 API Key。
