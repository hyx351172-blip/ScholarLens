# 新页面表格扩测 v12（20 张，2026-09-25）

## 结论

**当前离线表格修复还不能通过泛化验收，不建议直接接入生产解析链。**

冻结 v8 模型副本、v10 几何绑定和 v11 表头规则后，对 20 张未参与前轮调试的
表格重新执行本地识别。仅 **2/20（10%）** 候选通过几何门：一张改善、一张略微
退步；其余 18 张回退。两张通过样本都是 `unchanged_v10_success`，本组没有观察
到 v11 新增多层表头修复收益；这不等于证明该特定修复对所有适用表头都无效。

最重要的新发现：**模型结构与检测框相互一致，也可能一起把多条记录合并错。**
因此“完整网格 + OCR 唯一绑定”不是内容正确性证明。旋转表、单元格内公式、
无横线分行，以及严格 HTML 接口兼容性仍存在明确缺口。

本轮只新增测试、导出适配及报告，未修改冻结算法、生产解析、chunker、数据库或
前端，未提交/推送；付费 API 调用为 **0**。没有因评分结果重新调参或识别。

## 实验范围与协议

- 数据：已有 `OmniDocBench_academic_en_100.json`，其中 50 张非忽略表分布于
  41 页。排除之前 `selected_annotations.json` 的页面并集（10 页），确定性选择
  20 个新页面，每页取标注框面积最大的一个表，再按子集轮转抽样。
- 组成：`table_hard` 10、`v1.5` 9、`equation_hard` 1。选中页面标签包括少线框 7、
  `table_horizontal` 9、跨格 4、含公式 5、变形 1、缺省线框 2，标签可能重叠。
- 种子：`scholarlens-unseen-pages-v12-20260925`。选样不读取 Gold HTML/文字。
  裁图使用 **Gold bbox + 固定 12 px padding**，所以这是给定位置的组件测试，
  不是整页检测评测；裁剪也可能改变 Docling 的布局检测上下文。
- Docling：accurate TableFormer + EasyOCR，CPU 4 线程，禁用公式 enrichment，
  原图无损封装成单页 PDF；预先规定选择面积最大的原生预测表，不按 Gold 配对。
- Paddle：现有 PP-TableMagic v2 管线、v8 的 SLANeXt 1000 长度实验副本、全新 OCR，
  CPU 4 线程、MKLDNN 关闭，保持原实验配置（含方向分类关闭）。不是重用旧三表 OCR。
- 两组独立子进程运行，每例含模型加载限时 240 秒，不重试。所有失败都在 20 张
  分母中；被拒绝候选保持 Docling 基线，基线也缺失时记 0。**不按 Gold 择优。**
- 先冻结最终输出，再用固定官方 normalization / TEDS 评分；两个评分进程并行，
  单例限时 300 秒。本次 20/20 评分完成，无评分进程失败。
- 120 个输入文件（算法、模型、数据、裁图等）及两组输出均完成哈希校验；
  推理子进程不读取 Gold 文字/结构，主调度仅对受保护文件计算完整性哈希。

这是 **page-held-out from this development run**，不是严格 paper-disjoint。
例如 `case-03/17`、`case-07/19` 分别来自同一文件的不同页；UUID 文件也缺乏充分
论文标识。表格类型包括结算日期等示意表，不全是科研实验结果表；公开数据与模型
训练集是否重叠未知。后续若用这些失败案例改规则，本组应作为开发/回归集，而不能
再次宣称是未见测试集。

## 失败分析

1. **错误结构可通过几何一致性检查（优先级最高）**
   `case-13` 是结算日期表，多个正文记录未用横线分开。两个系统都将四条正文记录
   压到一行；当前 v10 看见自洽的检测框、逻辑格和 OCR 归属，因此接受。结构 TEDS
   仅 0.4。问题不只是 0.0017 的微小分差，而是门控无法发现这种共同错误。
   后续需要验证跨列文本行带/记录分隔证据，同时区分单格正常换行，不能只放宽门。
2. **单元格内公式不是普通 OCR 文本**
   `case-09` 两组结构 TEDS 均为 1.0，完整 TEDS 却只有 0.5869 / 0.6379。
   能观察到 `z = 0` 丢失 `z`、偏导分母/下标失真，也混有 LaTeX 与 Unicode 的
   表示差异。需要把真实漏字与格式差异分开，再做公式/数字问答验证。
3. **旋转方向问题早于表头修复**
   人工查看 `case-20` 裁图确认是 90° 旋转表。冻结配置没有启用方向校正，OCR
   大量退化为孤立数字，后续网格绑定无法恢复内容。下一轮应单独验证方向归一化。
4. **严格 HTML 协议与真实拓扑错误应分开**
   3 例报 `Unbalanced HTML tags`：01/11 缺少显式 `</tbody>`，12 则出现未匹配的
   `</tbody>`。另有 1 例跨度越界、2 例明确网格缺格。包装标签规范化可作为后续
   独立实验，但不得借机补猜缺失单元格或放行越界跨度；本轮没有自动补标签。
5. **几何门覆盖不足，拒绝原因不能一律称为“表头错误”**
   9 例最终为 `unsupported_header_prefix`。此前 v10 的原因包括：y 轴数量不符
   7、x 轴数量不符 5、x 轴不稳定 2、y 轴不稳定 1、OCR 歧义/未绑定 2（可重叠）。
   v11 是受限修复，不适用于这些输入；只调表头正则不能解决所有上游问题。
6. **检测与运行成本**
   Docling 在本次裁图条件下有 3 张未检出表，Paddle 有 2 次超时。CPU 子进程
   冷启动平均/中位耗时：Docling **67.8 / 55.6 秒**；Paddle **120.8 / 91.3 秒**。
   包含加载模型及两组并行时的资源竞争，不等于常驻生产服务时延。优先保障正确性，
   再另测模型复用、方向处理和有预算的疑难表分流。

## 测试脚本问题与恢复方式

版本记录代码查询 `version('docling')` 失败，原始 worker 状态因此是 20 个 failed。
这 **不代表 20 次模型转换失败**，也不能直接报告 20 个成功表格。

保留原脚本、日志、JSON 和哈希不动，新增导出阶段只对该精确的
`PackageNotFoundError` 恢复既定原生表导出：得到 17 个有效表、3 个 no_table。
超时和其他异常不走恢复；没有重新调用模型。恢复边界有专门单测。
