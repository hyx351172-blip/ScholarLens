## 逐条检查发现的问题

以下为对“该结论实际选中的原文”的 AI 离线检查，不是人工 Gold。
此前 AI 草稿标记的 8 项 support_gap，本轮都被评审模型判为 supported：

| 结论 | 证据缺口 | 本轮评审的问题 |
|---|---|---|
| L01-C005 | S1:U0003 / S2:U0012 是损坏的 `α r`，没有除号 | 评审把它复述为明确的 `α/r` |
| L01-C006 | S5:U0004 只说明注意力权重与冻结 MLP，没有 Wq/Wv 名称 | 核对了主要意思，忽略新增具体例子 |
| L01-C007 | 原文 S1:U0010 还要求应用到所有权重矩阵，回答遗漏该条件 | 评审把证据里的条件当成回答已经保留的条件 |
| L03-C001 | 所选公式/维度片段未说 W0 冻结 | 评审承认未明确写出，却用 standard LoRA setup 补全 |
| L03-C002 | S1:U0011 / S2:U0002 只有初始化，不含 A/B 维度 | 评审用标准 LoRA 维度及“没有矛盾”放行 |
| L03-C003 | S1:U0012 / S2:U0003 同样是 `α r` | 再次把损坏文本当作除法证据 |
| X02-C003 | S3:U0004 说本研究，回答说默认；具体矩阵名称也不在片段里 | 评审将研究设定等同默认行为 |
| X02-C004 | S8:U0006 有维度与低秩分解，但没有“仅这些参数可训练” | 评审用主要描述一致代替逐项支持 |

这些是“当前评审与已有开发期缺口分析的分歧”，不计算检测准确率、召回率或推广结论。
其中 L03-C001/C002 的模型评审理由明确借用了外部常识，违反本次冻结的仅选中证据协议。

另有 3 条保留人工裁决：

- **L01-C008**：所选证据支持“无额外推理延迟”，不直接支持宽泛的“性能一致”。
  模型给 supported，并在理由中进一步写出消除推理延迟；这比“无额外延迟”更强。
- **L03-C005**：所选片段明确首次 r 赋值且不调优；“减少超参数调整需求”是否可视作
  允许的直接推论，应由标注规范及人工裁定，不能自动视作对错。
- **X02-C005**：这是模型唯一拒绝的结论，但 contradicted 理由不可靠。
  回答明确说“其余所有参数均更新”，评审却解释成其他参数没有更新；同时把
  “除输出层外架构相同”理解成完全没有结构变化。“添加任务特定头”确实比证据更具体，
  但不能据此宣称已经找到明确矛盾。需要人工裁决，不把这个拒绝计为成功命中。

其余 11 条与此前 appears_supported 草稿一致；这只是逐条检查未发现明显缺口，
不是经人工认证的 11 条正确答案。

## 结论与下一步

工程层的隔离、限额、格式校验和日志符合预期；**语义层未达到启用要求**。
增加评审调用本身并未解决模型用常识补证据、忽略结论中次要限定词的问题。
同一模型系列生成与评审可能有相关错误，本次单轮开发集不足以量化这种影响。

建议下一步先人工裁决这 8 项缺口和 3 项措辞争议，再实现一个独立的小型对照：
把复合结论拆成维度、初始化、是否冻结、适用范围等原子事实，要求每项对应明确原文；
证据中无法判定的公式不猜符号。用包括正确改写与错误改写的配对样例校准评审，
避免仅重复同一批已知问题。原文子串匹配只能证明摘录真实，仍不能单独证明语义支持。

本轮不改提示词后重跑、不扩展证据、不自动修复答案、不启用线上评审。
按 `ai-product-dev-pack` 完成测试、追溯与兼容性验收，放行范围仅为本次实验报告，
不把单元测试全绿当成语义正确或生产启用批准。
