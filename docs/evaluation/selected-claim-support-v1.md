# 逐条证据支持检查 v1：离线实现与开发集

日期：2026-09-27。状态：**实验组件已实现，未接入默认问答，未调用真实评审模型。**

## 为什么要增加这一层

上一轮 sentence_v2 的真实生成实验保留了 22 条结论及 52 次引用片段选择。
虽然引用编号、原文位置和输出格式均可校验，仍出现了漏选维度/冻结条件、
从损坏的 `α r` 猜出除法、以及把研究条件扩大为默认做法的问题。
这些是语义支持问题，不能靠存在引用编号或正则表达式证明已经解决。

既有 anchored audit 工具会重新划分整段被引用来源；直接用于当前回答，
可能把生成时未选择的相邻句也交给评审。因此这里新增独立的 selected-anchor
协议，不改动、也不覆盖历史评测。

## 本轮实现

- `backend/chat/selected_claim_support.py`：从原始检索文档重建 catalog 和绑定，
  每条结论只发送其明确选择的原文范围，不展开整个 Chunk，不补邻句，不借用其他结论。
- 请求指纹覆盖问题、结论、所选片段、证据模式和评审提示词；拒绝过期、串题、串结论的结果。
- 严格解析 `supported / unsupported / uncertain` 及配套原因；评审不能返回新增引用、
  捏造摘录或修订回答。程序自行从所选原文提取评审引用。
- 仅当全部结论的有效评审都为 supported，才原样放行候选答案。
  unsupported / uncertain 会拦截整份候选；缺失、无效或失败的评审采用另一种错误状态，
  不把“核验没完成”伪装成“论文里没有答案”。
- 注入式异步 reviewer：显式有限调用预算、串行、超时、组件层不重试、异常停止；
  异常消息不进入结果。没有内置 API 客户端、密钥读取或自动联网。
- 即使模型全部评为 supported，`semantic_verified` 和 `human_verified` 仍为 false。
  `review_supported` 是模型意见，不是事实保证；误放行和误拦截都需要后续校准。

### 关键函数

| 函数 | 用途 |
|---|---|
| `prepare_review` | 校验生成输出并构建各结论独立的证据包 |
| `review_messages` | 构建仅含该结论及所选证据的模型请求 |
| `parse_decision` | 检查评审身份、状态、原因与引用来源 |
| `gate_answer` | 根据完整评审结果决定是否放行原答案 |
| `review_answer` | 有限预算的 reviewer 回调编排 |

未来真实模型适配器还需单独负责授权、模型和端点校验、token 上限、SDK 零重试、
费用/usage 记录以及持久化调用日志。本轮预算只限制回调次数，不声称能限制回调内部隐藏重试。
