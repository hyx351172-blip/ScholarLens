## 实现

新增 `scripts/table_record_reconstruction.py`，不修改冻结的 v10～v13 代码。

1. 仅处理 v13 唯一拒绝原因为 `aligned_multiline_row_ambiguity` 的候选。
   重新检查来源、HTML 与 OCR 一致性，并重新检测歧义；其他失败不被放行。
2. 一个正文行必须完整覆盖至少三列，且不能涉及表头、跨行或跨列单元格。
3. 一列短数字/单位记录作为锚点；至少另外两列有空间对齐、重复模式的
   记录开头。记录数量来自 OCR，不来自预设答案。
4. 续行必须位于明确的记录区间，并有缩进或前一行连字符支持。
   无法确定归属、缺少记录开头或候选划分冲突时保持回退。
5. 重建逻辑行、更新后续行偏移，保存旧/新 cell 关系和每条 OCR 来源。
   多处合并行一起处理；后面任一处失败，不能返回部分修复结果。

这不是“看到换行就拆行”。当前模式刻意有限：没有短数值锚点、没有足够
独立记录标识的表格不修；仅有普通多列段落也不能成为拆分依据。
未新增图像横线检测，本版使用缓存的 OCR 几何与文本模式作证据。
规则未包含样本 ID、特定日期/单位、正确行数或评分结果。

### OCR 框跨界的处理

原 OCR 框包含上下留白，有些相邻框相互重叠，不能把“完整框不能重叠”
当成记录不存在的证据。本版用 OCR 框**中间 40% 高度**的几何区域寻找
不相交的记录区间，保留原始 bbox，不裁掉原文字证据。

case-13 的逻辑横向分界为 y ≈ 103.49 / 140.85 / 166.35 / 215.45 / 276.10。
这些是推断的逻辑边界，不是图上真实横线；字符精确边界尚未验证。
将来用于引用高亮时应使用原 OCR 证据框，而非假定逻辑单元格框覆盖所有笔画。

## 限制及后续

- 本轮只有 **1 个符合入口条件的真实合并行正例**；主要反例是合成测试，
  不能据此宣称真实表格误拆率为零或具备普遍泛化能力。
- 有意在同一个单元格里排放多条数字/编号清单的表格，可能与真实记录极为
  相似；当前几何和文本模式不能完全证明作者的语义意图。
- 当前数据已经参与调试，属于开发/回归集，不是独立 held-out。
- 仍未处理缺失表、复杂 HTML 包装、表内公式 OCR，也不是 RAG 问答评测。
- 下一阶段可区分 HTML 包装错误与真实网格缺损；随后冻结规则、增加独立
  正反例验收，达标后再接入正式链路。
