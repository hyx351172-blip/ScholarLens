# 新旧回答模式对比 v1

日期：2026-09-27。范围：冻结证据的配对开发实验；不是 held-out、线上全链路或人工 Gold。

## 结论

**暂不把 `claim_bound` 设为默认。** 它增加了逐条结论的证据定位信息，但本轮
没有证明回答质量优于旧模式，且因句界校验导致两道本可回答的问题整份拒答。
引用编号和跨度合法并不意味着所选锚点充分支持结论。

预定 12 题 × 2 种模式：记录 22 次生成尝试、21 份模型响应、1 次连接失败；
空证据两组均不调用模型。首个 A01-legacy 在受限执行环境中连接失败，
无密钥连通性检查也失败；在获准的网络环境中检查返回 401，后续请求正常。
失败记录保留、不重试、不借用历史回答补齐。因此实际有 **11 组可配对案例**，
其中 8 道可回答、2 道论文无答案、1 道空证据。

## 配对结果

| 检查 | legacy | claim_bound |
| --- | ---: | ---: |
| 可配对的可回答题返回非拒答且有合法引用 | 8/8 | 6/8 |
| 可回答题返回固定拒答 | 0/8 | 2/8 |
| 无答案 / 空证据题返回固定拒答 | 3/3 | 3/3 |
| 配对非空样本生成平均耗时（10 题） | 5.03 s | 8.82 s |
| 配对非空样本生成中位耗时 | 5.18 s | 9.12 s |
| 同 10 题输入 token | 33,584 | 51,723 |
| 同 10 题输出 token | 1,857 | 3,420 |
| 同 10 题总 token | 35,441 | 55,143 |

本轮配对观测中新模式平均耗时约高 **75.5%**、总 token 约高 **55.6%**。
每题仅运行一次，不能视为稳定性能、显著性结论或金额涨幅。这里只计生成阶段，
不含解析、切分、检索、Embedding、规划器、重排序或模型配置读取时间。

8/8 与 6/8 是**可用输出和引用格式**计数，不是回答正确率或引用蕴含率。
逐题核心信息及有疑点的限定词由 AI 对照原文检查，仍需人工确认。

### 全量分母（不隐藏失败）

- 旧模式：9 道预期可回答题中 8 道返回带引用回答，1 道连接失败；3 道负例拒答。
- 新模式：9 道预期可回答题中 7 道返回带引用回答，2 道格式拒绝；3 道负例拒答。
- 两组请求均最多 2,000 输出 token；收到的 21 份响应均为 `finish_reason=stop`，没有截断。
- 新模式 11 份真实响应均可解析为 JSON。两份拒绝是业务校验失败，不是坏 JSON。
- 新模式已交付的 47 条结论含 106 次证据锚点引用；答案索引、原文索引和编号均精确匹配。
  这证明定位真实性，不证明全部 47 条结论在语义上有充分支持。
- 全部已收到响应的 usage 合计：输入 88,088、输出 5,940，总计 **94,028 token**。
  A01-legacy 连接错误没有 usage，未将其虚构为已确认的零费用。

## 实验设置与公平性

- 固定选择 A01/A02/A03/A04、B01/B03、L01/L03/L04、X01/X02、E01。
  9 道可回答，2 道论文没有结果的负例，1 道空证据控制；未覆盖历史切换 H01。
- 证据来自 `output/e2e-document-scope-v1/answer-*.json` 的已保存最终来源，
  内容、顺序和来源编号两组一致，不重新检索，也不重新解析或修改数据库。
- 两组均重新生成，不把昨天的旧答案与今天的新答案混为同轮对照。
- 模型为项目配置的阿里云百炼 `qwen3-vl-plus`；temperature=0、max_tokens=2000。
  串行执行，按题交替先旧后新 / 先新后旧；只有回答模式及其预期的提示词与格式差异。
- 调用真实 `ChatService.generate_answer`，保留各自生产提示词、渲染与 guard。
  测试适配器只截获外层客户端，统一设零重试、60 秒网络超时和90秒单调用总截止。
  旧模式生产客户端原本未显式关闭重试，本实验为控制费用将其关闭；不测重试韧性。
- 未重启服务：本地 8501/8502 没有可用配置服务，使用本 checkout 已有 `.env`，
  仅在内存读取密钥，并验证 HTTPS、阿里云目标域名和模型名称。
- 请求、代码、题目与原始来源共 604 个冻结文件在实验前后保持一致。
  标签只用于离线汇总，未放入模型提示词。生产默认模式和前端未更改。
- 用户明确批准最多22次生成，不额外调用评审模型；本轮没有付费 judge。

这比较的是**两种完整生成模式**，不只是 JSON 格式一个因素：新模式同时改变了
证据分段表示和系统提示词。不能把差异完全归因于结构化输出本身。

## 发现的问题

### 1. 句界启发式过严，且整份拒绝放大影响

A02 原始JSON第4条使用分号连接正文与表格的差异；A03 第5条使用分号比较
不同维度下的注意力表现。`_single_sentence` 将分号作为边界，于是拒绝整份输出。
逐条离线重放定位到上述两条，其余条目能单独通过当前结构检查；这只是诊断，
**没有删除失败条目、重新渲染用户答案或改写分数**。

模型已经返回主要答案，不意味着它遵守了严格的逐条格式要求；同样，这两个拒绝
也不是检索没找到证据。当前固定“证据不足”提示掩盖了真实的格式失败原因。

### 2. 锚点确实存在，但没有选到完整支持范围

- B01-C002 声称50%比例，选择的 S8:E0006 停在采样描述之前；比例位于
  未选择的 S8:E0007。S1:E0001/S6:E0001也没有比例。
- L03-C002 同时包含矩阵维度与初始化，却只选择初始化段 S1:E0005/S2:E0002；
  维度信息位于未被这条选择的 S1:E0003。
- L01-C008 的绑定在句子结束前被480字符分段切开，仅选择前半段，未选择下一锚点。

这些情况必须区分“整块来源包含支持”与“该结论实际绑定的细锚点充分”。
网页 `[Sx]` 仍可打开完整 chunk，不能因此把错误的细锚点选择判为正确。

### 3. 限定词与公式依然需要语义 / 原文检查

- X02-C003 把“本研究只适配注意力”变成“LoRA默认仅适配注意力”，结构校验无法发现。
- L01-C009、L03-C004 的原文片段仍是压平的 `α r`，模型输出 `α/r`。
  公式在论文中可能正确，但本轮选中片段没有清晰保留除号，不能宣称证据直接证明。
- B01-C002 的中文把50%采样条件写得像判断概率，需改进表达而不仅是补引用。

以上属于有针对性的 AI 复核，不是对全部新旧断言的穷尽审计，未产出“语义准确率”。
详细逐题草稿见 [AI复核记录](answer-mode-ab-v1-review.json)，人工字段保持空值。

## 下一步建议（本轮未实施）

1. 先把“引用ID / 证据归属”硬校验与“句界 / 文风”启发式区分，
   分号不应直接造成整份回答丢失；保留无引用和未知引用的严格拒绝。
2. 改进完整句 / 相邻锚点的选择，减少在数字、矩阵维度与句尾处断开支持范围。
   不能无条件扩张到整篇论文并把它当作模型已正确选择。
3. 给用户显示真实失败类型；不能把格式错误、调用错误都解释成文献没有答案。
4. 先用本轮冻结原始响应做离线回放，确认改动边界，再申请少量真实复测。
   不必再做一轮大规模付费评审，暂不默认启用新模式。
