# 表格可靠性修复 v13：合并行拦截与方向校正

日期：2026-09-25。状态：**离线开发回归完成，未接入生产解析/知识库**。

## 结论

本轮修复了两类缺口：阻止多条记录挤在一行的候选继续被采用，以及在
可靠方向证据下先旋转原图、再完整解析。20 个既有样本相比 v12：
**2 个改善、0 个退步、18 个不变**。旧的 3 个表头/网格控制样本输出不变。

| 指标 / 全部 20 个样本 | 原 Docling | v12 有效输出 | v13 有效输出 |
|---|---:|---:|---:|
| 官方完整 TEDS 均值 | 0.533177 | 0.535640 | **0.584332** |
| 官方结构 TEDS 均值 | 0.729655 | 0.729655 | **0.740280** |

这些是**表格组件分数，不是问答准确率**。20 个样本已参与错误分析与修复，
现在是开发/回归集，不能再次称为新 held-out；也不是全页或论文隔离测试。
整体仍未达到可宣称复杂表格问题全部解决的程度。

## 1. 多记录合并：修复误放行，不擅自拆行

case-13 的物理检测框和结构预测都把四条正文记录合成一行。旧规则只验证
OCR 是否唯一落入单元格，因此错误结构仍能通过。

新增 `table_candidate_safety.guard_candidate`：

- 在同一逻辑行的至少两列中寻找至少三个纵向对齐的 OCR 行带。
- 这是“可能合并了多条记录”的歧义信号，不是确定的记录边界。
- 对可疑候选增加 `aligned_multiline_row_ambiguity` 拒绝原因，保留原文本、
  OCR IDs、单元格和 span，不凭换行编造新行。
- 单列多行、普通一/两行换行、显式表头、跨行/跨列单元格不触发该检测；
  原本已失败的候选不会被该规则重新放行。多列长段落仍可能被保守拒绝。

case-13 的有效 TEDS：**0.286784 → 0.288511**，来自回退到原 Docling，
并非恢复出了正确四条记录。这一步解决的是“不该接受的结果被接受”，
后续仍需要可靠的行边界重建。

## 2. 旋转表格：方向探测与完整解析分开

初版对三个目标裁图分别运行四方向完整 OCR。case-20 首个方向就识别了
239 个文本框，整个方向探测在 **300 秒**超时。保留该次输出及回退记录，
没有把部分结果当成功，也没有延长超时隐藏失败。

随后单独建立 v13-bounded：

1. 对 0/90/180/270° 四个方向使用已有本地文本检测模型。
2. 每方向最多取 24 个空间分散的水平文本框；只识别宽高比不超过 12 的
   文本前缀，用于判断方向。该抽样不读取标准答案、不按词义筛选文本。
3. 用 OCR 置信度、可读文本量及方向间分差选择方向。最低质量 0.65、
   与原方向及第二名的分差均至少 0.08；模糊情况保持原方向。
4. 确认非零方向后，旋转**全分辨率原图**，重新执行完整 Docling 与 Paddle
   表格解析；不把抽样文本或原方向 OCR 坐标混入最终结果。

case-20 选择逆时针 270°（即顺时针 90°）：方向得分 0.974626，第二名
0.238123。两个正常方向控制样本 case-09/case-13 均保持 0°。

| case-20 | v12 | 校正后的有效输出 |
|---|---:|---:|
| 完整 TEDS | -0.032236 | **0.939882** |
| 结构 TEDS | 0.787500 | **1.000000** |

有效结果来自校正后 Docling（16 行 × 9 列）。Paddle 原始 HTML 仍有标签
不平衡，继续拒绝；其官方归一化诊断分数为 0.671306，不参与输出选择。
因此不能把此提升解释为 Paddle 网格修复成功。

Docling 的 143 个原生单元格均保存了回到原裁图、原页面的 bbox，缺失 0。
原生 TOPLEFT/BOTTOMLEFT 坐标先统一，再逆旋转；另存 Paddle 原始 OCR
坐标映射，两个 OCR ID 命名空间明确区分。原始 PDF/图片和旧解析产物不变。

## 3. 方法、资源与评分边界

- 未更改 v10/v11/v12 冻结代码、模型权重、Gold 或既有产物；前后 SHA256 校验通过。
- 20 个样本全部保留在均值分母；3 个原始无表结果仍为 0，未筛除困难样本。
- 只对 case-20/13/09 运行方向模型；其余 17 个只做候选安全回放，
  **没有宣称 20 个全部重新推理或全部验证方向算法**。
- 新输出冻结后独立评分。18 个有效 HTML 与 v12 字节相同，验证哈希后复用
  已有官方分数；case-13 与 case-20 重新调用官方 TEDS。评分器检查有效 HTML
  与候选准入/基线回退契约一致，不能用 Gold 选择输出。
- 保留官方原始负分，不静默截断到 0。此前负分原因见 v12 审计。
- 全部本地 CPU/缓存模型，无下载，**付费 API 调用为 0**。

| 有界方向探测 / 本地耗时 | 秒 |
|---|---:|
| case-09，四方向 | 69.94 |
| case-13，四方向 | 53.95 |
| case-20，四方向 | 144.33 |
| case-20，校正后 Docling 冷启动完整解析 | 80.36 |
| case-20，校正后 Paddle 冷启动完整解析 | 169.73 |

两条完整解析路线并行；以上是逐任务 wall time，不能相加当作用户端延迟。
方向探测 240 秒、完整解析每任务 240 秒，均无自动重试。当前 CPU 延迟仍高，
不宜在生产中对每张正常表无条件运行四方向识别。
