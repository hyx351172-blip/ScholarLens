# ScholarLens 真实完整链路验收 v1

日期：2026-09-25。结论：**主链路已贯通，但回答质量验收未全通过。**
这是单篇已使用过的 Attention 论文开发集冒烟，不是 held-out 或多论文泛化评测。
本轮不修改产品实现，不提交/推送，不把发现的问题自动修复后覆盖原始结果。

## 环境与范围

用户恢复 Docker 后确认 Milvus、MinIO、etcd 健康；启动四个后端与 Vite 前端。
真实调用项目上传接口和 Chat API，无检索/模型 mock。按前端默认 Docling 路径
解析，结构感知切分在提取服务内执行；8001 Chunking API 健康，但此模式不经过它。
VLM 修复关闭；API 问答 Top-K=10、阈值0.1、multi-query开启、reranker关闭，
temperature=0、max_tokens=1000。UI 使用页面默认模型/检索配置另测一题。

- 测试知识库：`E2E-v1-20260925-isolated` / `kb_1790349563807`。
- 新文件：`file_20260925_2362318a`，`1706.03762_attention-is-all-you-need.pdf`。
- PDF SHA256：`2f4e58b8b96b998c022b841e6391a02f732bad62226b0e5d0187593fb21ffd41`。
- 原有知识库未改动；测试知识库与服务保留，方便复查。
- 一次 PDF 入库任务、4 次非流式 Chat 请求、1 次浏览器流式 Chat 请求。
  会消耗已有 Embedding/LLM API 额度，可能包含内部规划/检索请求；未执行付费 judge，
  不能将 5 次 Chat 请求等同于全部供应商 API 调用次数。本次接口未返回完整计费信息。

### 原文自身的数值差异

原始 PDF 第8页表2为41.8，而同页6.1正文为41.0。本题明确指定表2，故按41.8核验。
用PDF技能读取本地原文，并核对真实返回的表格Chunk；没有凭模型常识改写标准答案。

### 生成层问题（后续优先修复）

1. **非法引用未拦截**：结论原答案包含“训练速度……架构 `[S母公司]`”。
   同句前面虽有有效`[S1]`，也不能因此忽略非法标记。
2. **拒答后继续添加外部知识**：无答案题补充GPT-4发布年份，并把论文证据标到该说明上。
   无论外部事实是否正确，都违反仅根据本次检索证据回答的合同。

初始运行器只扫描`[S数字]`，错误地把结论引用格式视为通过。本轮先写失败测试，
再加强**测试检查**以捕获`[S母公司]`，离线复审原答案；没有再调用模型挑选更好的答案。
保留原始`answer-*.json`，修正后的结果单独写在`audit.json`中。
测试检查不具备自动证明逐句蕴含的能力，语义问题来自本轮人工式原文/证据审查。

## 前端实际操作

1. 文献库进入独立测试知识库，显示1文档、54 chunks、已索引。
2. 打开文档，切分块页显示54条；表2内容和28.4/41.8可见。
3. 问答页选中独立测试知识库，发送表2问题；流式输出完成，答案仅引用S4。
4. 点击S4打开证据面板：显示第8页、表2原文、`logical_table_0002:part_0001`。
5. 点击“打开原文 PDF”，其可见链接为
   `http://localhost:8000/document/file_20260925_2362318a/pdf#page=8`。
   内置浏览器未呈现可核验的PDF页画面，点击也未产生可观察的新标签。
   文档内嵌PDF区域曾显示黑色，**不能宣称已视觉验证PDF自动跳到第8页**。
   需在正常支持PDF预览的浏览器补测，尚未证明是应用故障或浏览器能力限制。

另有三项次要观察：

- 从文档页切换问答时曾出现空白内容区；刷新后从概览进入问答可正常操作。
  记录为待复现UI问题，未凭一次现象断言根因。
- 答案只引用S4，底部却标“本回答引用的证据 10个片段”，实际显示全部召回来源。
  建议区分“已引用证据”与“检索候选”，避免用户误解。
- 表2被绑定到`5 Training / 5.4 Regularization`，页码正确但章节语义可疑；
  这与浮动表位置有关，未影响本次数字回答，作为后续元数据质量问题保留。
