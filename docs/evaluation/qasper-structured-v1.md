# 候选对象结构化回答实验

日期：2026-09-26。此轮为上一轮证据规划实验的延续，正式聊天未改动。使用 ai-product-dev-pack 的先测后实现流程，拒绝为提高指标而放宽原文匹配校验。

## 设计

复用 `qasper-evidence-plan-v1` 的20份已校验候选，不再调用规划模型。逐个候选输出 `candidate_id/entity/status/answer/evidence`，每个ID只能出现一次且必须覆盖；supported 必须带真实来源内的连续原文摘录；insufficient/irrelevant 不得夹带答案。确定性渲染器添加引用，对局部证据不足保留其他候选的答案；结构非法则固定拒答。

这是新的实验渲染路径，并非原 guard 的生产替换。严格 JSON 由提示词要求和本地校验实现，未使用供应商强制 JSON Schema 或格式修复重试，因此真实格式失败也纳入结果。

校验仅证明引用存在和摘录匹配，不能证明答案被摘录蕴含，也不能证明候选与问题相关。生成时不加载标签；20题已用于开发，不是 held-out。相同对象在原计划中有多个摘录时仍按多个候选ID处理，可能导致冗余与矛盾，这是本实验设计的限制。

输入、缓存计划、代码SHA-256均在 `output/qasper-structured-v1/manifest.json` 冻结。每题保存原始JSON文本、解析对象、渲染结果、候选、token与时延。为复用评分器，`draft` 与 `answer` 都是渲染后的文本，真正原始输出在 `structured_raw`；不能用 draft/answer 比较宣称防护前后收益。

## 关键问题

- 00：问 out-of-domain data，回答转成 Common Crawl 的词向量初始化数据。摘录是真实的，但没有解决原问题对句子编码器训练数据的指代，属于目标偏移风险。
- 04：问 DSL 有哪些语言，回答“14种语言、6组”。回答没有列出语言名称，却被标为 supported；证明来源匹配无法代替回答充分性检查。
- 05：数据集大小题返回非法JSON（额外闭合括号），两个候选均为 insufficient，仍没有利用353段会话/40名说话者的信息。
- 07：评价题的部分候选给出实验表现，但整段JSON非法而被拒绝；没有形成可用答案。
- 02：模型把逐字摘录改成含 `...` / `[...]` 的拼接摘录，校验拒绝，不能把这种失败计作模型正确判断无答案。

## 复现

```powershell
python tests/integration/run_structured_answer.py
python tests/integration/score_qasper_guard.py --output-dir output/qasper-structured-v1
```

每题最多1次回答调用，共20次，无重试；已有结果经ID和代码哈希校验后跳过。耗时仅包含新回答调用及校验，不含缓存规划成本，不能直接当作整个双阶段链路耗时。

本轮新调用总计116,313 tokens（输入107,160、输出9,153）；不含上轮已经花费的规划成本。评分器移除引用并使用官方token F1函数，但这是开发子集且输出形式改变、没有逐题完整蕴含审计，不是官方完整成绩或语义准确率。

暂不接入生产。结构约束增加了可检查性，但不能自动修复语义指代，并引入格式失败。下一步应先整理人工语义验收集（目标对象、所问属性、答案是否充分、证据是否支持），再决定是否保留规划层；不要继续仅用固定拒答计数或token F1驱动优化。
